# Go에서 `fasthttp`를 어떻게 이해하면 좋을까

Go 서버 코드를 보다 보면 `fasthttp`라는 이름을 종종 마주친다. 처음에는 `HTTP/1.1`, `HTTP/2`처럼 HTTP 표준의 다른 버전이나 프로토콜처럼 느껴질 수 있다. 이름이 `fast + http`라서 “더 빠른 HTTP 표준이 있나?”라고 오해하기도 쉽다.

이 메모는 그 헷갈림을 정리하기 위한 글이다. 핵심은 간단하다. **`fasthttp`는 새로운 HTTP 표준 프로토콜이 아니라, Go에서 사용할 수 있는 HTTP server/client 패키지다.**

## 1) 왜 이름만 보면 HTTP의 다른 표준처럼 느껴질까

오해가 생기는 이유는 자연스럽다.

- 이름에 `http`가 직접 들어간다.
- `fast`라는 단어 때문에 기존 HTTP 표준의 상위 버전처럼 보일 수 있다.
- 실무 대화에서 “`net/http` 대신 `fasthttp`”라는 문장을 들으면 표준 교체처럼 들리기도 한다.

하지만 HTTP 표준은 IETF RFC로 정의되는 언어 독립 규약이고, `fasthttp`는 Go 생태계 안의 라이브러리다. 둘은 비교 대상의 계층이 다르다.

## 2) 실제로 `fasthttp`는 무엇인가

`fasthttp`는 Go용 HTTP server/client 패키지다. 즉, HTTP를 처리하는 Go 구현체 중 하나로 보는 편이 정확하다.

여기서 중요한 점은 다음 세 가지다.

- `fasthttp`는 새로운 HTTP 표준을 정의하지 않는다.
- Go 생태계 안에서 `net/http`와는 별도로 존재하는 선택지다.
- `net/http` API를 그대로 따르는 상위호환으로 보기 어렵다.

그래서 비교 축은 “HTTP 표준 vs `fasthttp`”가 아니라, 보통 “Go의 `net/http` vs `fasthttp`”에 가깝다.

## 3) 왜 `net/http` 외에 이런 구현이 따로 존재할까

이 질문은 “왜 별도 구현이 필요한가”에 가깝다.

`fasthttp`는 주로 일부 고성능 시나리오를 더 강하게 겨냥한 라이브러리로 소개된다. 요청 처리의 hot path에서 비용을 줄이는 방향을 우선하는 선택이라고 이해하면 된다.

반대로 일반적인 웹 서비스 개발에서는 `net/http`가 더 익숙하고 다루기 쉬운 경우가 많다. 실제로 `fasthttp` 쪽 설명도, 대부분의 경우에는 `net/http` 사용이 더 적합할 수 있다는 뉘앙스를 함께 담고 있다.

즉, `fasthttp`의 존재 이유는 “표준 대체”라기보다 “특정 목표를 위한 별도 최적화 선택지”에 가깝다.

## 4) “성능 지향 설계”는 어떻게 이해해야 할까

성능 지향 설계는 보통 다음과 같은 방향을 뜻한다.

- hot path에서 메모리 할당을 줄이려는 설계,
- 낮은 오버헤드를 지향하는 처리 경로,
- 객체 재사용과 할당 감소를 중시하는 API/구현 선택.

이런 특성은 워크로드에 따라 의미 있는 차이를 만들 수 있다. 다만 그 사실이 곧 “항상 더 빠르다”는 결론으로 이어지지는 않는다.

실무 성능은 네트워크, 애플리케이션 로직, 저장소 I/O, 배포 환경, 트래픽 패턴이 함께 결정한다. 그래서 라이브러리 단위 벤치마크는 참고 자료로 보되, 서비스 맥락에서 다시 검증하는 것이 안전하다.

## 5) 그래서 실무에서는 어떻게 받아들이면 좋을까

실무에서는 `fasthttp`를 “기본값”보다 “조건부 옵션”으로 받아들이는 편이 현실적이다.

먼저, `fasthttp`가 프로토콜 대안이 아니라 Go 라이브러리 선택지라는 점을 분명히 두는 것이 좋다. 그다음, 성능 요구가 실제 병목인지 확인하고, 그 병목이 HTTP 처리 경로에서 발생하는지 측정으로 확인한다. 마지막으로, 마이크로 벤치마크 숫자만 보지 말고 서비스 단위 부하 테스트와 운영 지표로 기대 효과를 검증하는 순서가 안전하다.

이 관점에서 보면 `fasthttp`는 “항상 더 좋은 답”이 아니라, 목표와 제약이 분명할 때 검토할 수 있는 성능 지향 선택지다.

## 6) 짧은 결론

- `fasthttp`는 HTTP/1.1, HTTP/2 같은 표준 프로토콜의 대안이 아니다.
- `fasthttp`는 Go용 HTTP server/client 라이브러리(구현체)다.
- `net/http`의 상위호환이라기보다, 다른 우선순위를 둔 별도 선택지에 가깝다.
- 실무에서는 벤치마크 결과를 일반화하기보다, 적용 맥락과 측정 결과를 함께 보고 판단하는 편이 안전하다.
